# T002: device-ping-pong

Potential device round trip without an intervening use.

## Trigger and boundaries

A confirmed Tensor returns to its known starting CPU/CUDA device through consecutive conversions, in one straight-line block or call chain. Unknown calls, intermediate consumption, and control-flow boundaries stop the sequence. Returning to a different fixed CUDA index is excluded.

## Explanation

The visible conversion sequence returns this tensor to its starting device without a tracked intermediate use.

## Manual suggestion

Review the purpose of both transfers and remove the round trip manually only if its synchronization and data semantics are unnecessary.

```python
import torch
x = torch.ones(4, device="cpu")
y = x.cuda().cpu()

z = x.cuda()
consume(z)        
w = z.cpu()
```
